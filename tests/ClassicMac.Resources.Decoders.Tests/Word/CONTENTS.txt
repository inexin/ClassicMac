Word test documents for ClassicMac (our own synthetic content; redistributable)
================================================================================

Made in SheepShaver (Mac OS 9.0) on 2026-10-03.
- Microsoft Word 5.1a (About box: "Version 5.1a, November 4, 1992"): files w51-*.
- Microsoft Word 4.0: files w4-*.
- Microsoft Word 6.0 (pre-installed folder "Word 6.0", not 6.0.1): files w6-*.
- Format: MacBinary (.bin).
  - w4/w51: type WDBN, creator MSWD, data fork only.
  - w6: type W6BN, creator MSWD; the data fork is an OLE2 compound file (D0CF11E0, nFib 104) and there is a small
    resource fork. Word 6 user name "Fixture" (it was a generic "Name"); the author in summary info = "Fixture".
- Word's "Your Name" preference was set to "Fixture" before any save, so no personal name is stored.
- The default/Normal font is New York 12 (Word 5.1a installer default).

HOW THE DOCUMENTS WERE MADE (read this)
- The content was NOT typed run by run. Typing into the emulator is unreliable (keyboard-layout mapping) and slow.
- Each document was authored as Mac RTF (source-rtf/*.rtf, generated by source-rtf/gen_rtf.py).
- Each RTF was opened in Word ("Interpret RTF" = yes) and saved with Word's own Save as "Normal" (native) format.
  So every byte of the .bin files was written by Word's native writer. Word's RTF import decides the stylesheet,
  font table etc.

"-fast" FILES ARE NOT FAST-SAVED
- The -fast variants are edited versions of the same documents, but Word did FULL saves every time.
- The edit text sits inline in the text stream, in document order (checked in the data forks).
- What was tried:
  - "Allow Fast Saves" ON in Word 5.1a Preferences;
  - Save As to a new name, then edits + Cmd-S;
  - close, reopen from disk, more edits + Cmd-S (in both Word 4 and 5.1a).
- In both versions the "Fast Save" checkbox in the Save As dialog stayed disabled, even for a document typed natively
  in Word (w51-native) and reopened. The cause is unknown.
- So these files do NOT contain multi-piece / complex (fast-saved) piece tables.
- Word 6 also did full saves:
  - "Allow Fast Saves" was ON (Tools > Options > Save) and autosave was off;
  - each -fast file was saved, closed, reopened from disk, edited, then Cmd-S;
  - the FIB shows fComplex=0 and cQuickSaves=0 in every w6 file;
  - a separate 64 KB test document behaved the same, so it is not a small-document threshold.
- Probable cause: something in this environment (SheepShaver plus the hfsutils-formatted work volume). Unverified.

Word 98: files w98-* (made 2026-10-06; see the WORD 98 section at the end). SheepShaver could not be used (it crashes
whenever Word 98 opens a document), so they were made in QEMU 11.1 (mac99) with Mac OS 9.2.2.
Word 3.01: launches, then hangs Mac OS 9 on startup, so no files.

WORD 98 (w98-*.bin), made 2026-10-06
--------------------------------------------------------------------------------
- Microsoft Word 98 Macintosh Edition ('vers' 8.0), in QEMU 11.1 (mac99) running Mac OS 9.2.2.
- Format: MacBinary III. Type W8BN, creator MSWD. The data fork is an OLE2 compound file (D0CF11E0, wIdent A5EC,
  nFib 193). There is a 286-byte resource fork.
- The User Information name was "Fixture" before any of these files were opened. Summary info Author and Last saved by
  are both "Fixture". No other personal name is in the files (checked for "Lars" in ASCII and UTF-16).
- Base files: the same source RTFs (source-rtf/*.rtf) opened in Word 98 and saved with Save As > "Word Document".
  They are full saves: FIB fComplex=0, cQuickSaves=0. Content is as in BASE DOCUMENTS above.
- The Mac file name of w98-picture-footnote(-fast) inside the MacBinary is "w98-picture_footnote(-fast)", with an
  underscore.

"-fast" FILES ARE REAL FAST SAVES (unlike w4/w51/w6)
- Allow Fast Saves was ON (Tools > Preferences > Save).
- Each -fast file is a Finder duplicate of the base file. It was opened in Word 98, edited once, then saved with Cmd-S.
  Edits: "FAST START " typed at the very start; then down-arrow twice and " FAST MID" typed.
- Every -fast file has FIB fComplex=1 and cQuickSaves=1. The file grew by about 9-10 KB (the appended fast-save data).
- Final text (as on screen before saving):
  w98-plain-fast:            "FAST START Plain text test document." / "Mac Roman: FAST MID é ü ß …" (3rd paragraph)
  w98-formats-fast:          "FAST START Format: Normal run." / "Format: Itali FAST MIDc run." (" FAST MID" italic)
  w98-paragraphs-fast:       "FAST START Heading One" / " FAST MIDCentered paragraph." (centred)
  w98-table-fast:            "FAST START Table follows." / cell A2 = "A2 FAST MID"
  w98-picture-footnote-fast: "FAST START Picture follows:" / "Text with a f FAST MIDootnote<REF 1> here."
- Everything else is as in the base documents. The hidden run "Hidden run." is present but not displayed.

w98-prm-fast.bin (made 2026-10-06): a fast save whose only change is paragraph formatting
- A Finder duplicate of w98-plain. It was opened in Word 98 with Allow Fast Saves on. The cursor was put in the 2nd
  paragraph ("The quick brown fox ...") and Cmd-E (centre) pressed, then Cmd-S. There was no text edit.
- FIB fComplex=1, cQuickSaves=1. The piece table has 4 pieces. Piece 1 (CP 81-82, the 2nd paragraph's paragraph
  mark) carries Prm 0x010A: a Prm0 with isprm 0x05 (sprmPJc), value 1 = centred. The other pieces have Prm 0.
- Text is identical to w98-plain. Only the 2nd paragraph is centred.
